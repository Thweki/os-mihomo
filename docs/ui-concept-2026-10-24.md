# Mihomo 原生 UI 设计方向（2026-10-24）

## 目标

保持 OPNsense 的原生导航、页面密度与交互语言，优先让用户准确判断当前网络行为，再执行明确限定范围的改动。
本轮只制作可交互设计稿，未更改插件源代码、未部署、未连接或改动设备。

## 主题继承：用户明确要求

OPNsense 可以安装不同主题，插件必须始终与当前主题一致。

- 使用核心主题提供的 `nav-tabs`、`content-box`、表单、表格、按钮和告警样式；插件不定义独立色板。
- 不提供插件主题开关，不维护固定的“插件深色/浅色”两套配色。
- 自绘图表读取当前主题的语义角色或对应原生组件的计算样式，文字、背景、轴线、图例与状态同步更新；主题变化时重新取值。
- 颜色之外同时保留文字、形状、标记，避免只凭颜色判断状态。
- 设计稿的主题样例放在验稿控制中，模拟更换 OPNsense 外壳；它不是产品设置。原型外壳的样例色值不能复制进插件生产代码。
- 灰紫主题仅为自定义角色样例，证明设计可以整体换色；不代表已验证设备上所有第三方主题。落地后需在真实主题下验收。

此要求已加入 AGENTS.md，作为后续实现约束。

## 页面与交互

| 页面 | 优先信息 | 操作边界 |
|---|---|---|
| 运行概览 | 服务运行/自启、实时统计、逐接口实际去向、需要核对的差异 | 读取为主，服务操作放入明确入口并展示影响接口 |
| 路由策略 | 当前生效与策略配置分开；明确 TCP、UDP、DNS 和内网直达 | 编辑形成待应用状态，预览差异与影响范围后应用 |
| 参数设置 | 当前值、保持原值、固定值清楚可读 | 固定项使用文本；编辑后才出现相关待应用栏 |
| DNS 路径 | 按接口展示客户端→应答服务→上游；注明 DoH/DoT/IPv6 限制 | 只读，不附带应用/导入/重启栏 |
| 配置对照 | 页面/文件/运行三方分列；未知运行值明确标注 | 只读筛选与刷新，“一致”不掩盖未报告项 |
| 订阅更新 | 来源是否已验证、最近执行记录、备份与失败处理 | 先预览整体替换影响；重启选择独立可见 |
| 日志 | 明确来源、行数、过滤和刷新状态 | 纯文本显示；读取失败/无日志/无匹配分别反馈，清空单独确认 |

## 关键决策

1. 概览不把所有健康状态塞进红色“启动前”警告；差异只说明实际受影响的接口。
2. “全部代理”不能代替实际 pf 覆盖：当前示例显示 TCP 全部、UDP 53/500/4500，并标明需要核对。
3. 页面只显示改动后的相关应用入口，不让只读页常驻一组写入按钮。
4. 变更预览列出当前值、目标值、受影响接口、写入对象及校验/备份步骤。
5. 自启与当前启停分开，服务停止/重启前明确对绑定客户端的影响。
6. 内存读数标明数据来源 RSS；不可获取的读数应标“不可用”，不写 0 假装正常。
7. 统计值限制小数位；保持原值和固定字段仍显示内容。

## 本轮验证

- JavaScript 语法检查通过；浏览器没有脚本异常。
- 五页切换、路由编辑→待应用→预览→模拟应用、DNS 只读、日志过滤/来源空态均已在本地验证。
