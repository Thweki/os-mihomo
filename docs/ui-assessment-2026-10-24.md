# UI、实际功能与交互评估（2026-10-24）

## 结论

原生集成与主要只读功能已具备实用基础：导航、表单、表格与 OPNsense 的深色主题一致，实时数据、DNS 路径、配置对照、策略编辑弹窗和日志读取均可使用。
当前主要短板是**显示的状态不够可信、操作边界不够清楚**，尚不适合让用户仅凭概览或策略页判断完整网络行为。

共记录 10 项：高优先级 1 项、中优先级 7 项、低优先级 2 项。这里的高优先级指可能误导运维判断，并非本轮发现设备被改动。
优先补实际策略对账（UI-05），再收紧只读标签的写入入口（UI-04）、修正内存与禁用控件显示（UI-02/UI-09）。

## 范围与方法

目标：`https://192.168.1.1/ui/mihomo/`，OPNsense 26.7.7，当前深色主题。
使用 agent-browser 独立会话，在真实设备上检查页面、只读标签、筛选、分页和取消对话框。
不保存表单、不应用设置、不切换代理或运行模式、不执行测速、连接断开、订阅更新、服务启停或绑定自检。
配置、开机自启、pf/NAT、IPv4 路由与 Unbound 指纹在检查前后核对；凭据不写入报告。

## 已确认的基础能力

- 概览显示真实流量、代理组与连接；浏览器观察到的概览请求走同源 `/api/mihomo/*`，返回 HTTP 200。
- VPN → Proxy Suite 提供 Mihomo、设置、订阅、路由策略、日志五个入口。
- 设置使用原生表单、折叠分组、帮助与锁图标，配置对照提供页面 / 文件 / 运行三列。

## 发现

### UI-01：运行期间仍使用“启动服务前”的警告标题（中）

概览正在显示连接和实时流量，SSH 亦确认 mihomo 进程存在，但红框标题仍是“启动服务前请先确认以下事项”。
内容把 DNS 劫持影响描述成“本机后面所有客户端”，未在该处标明实际覆盖接口。
建议按运行状态切换标题，并列出受影响接口，使用户能区分当前风险与启动前置条件。

证据：[概览桌面截图](screenshots/audit-20261024-dashboard-desktop.png)。此项为静态可见问题。

### UI-02：内存卡片显示 0 B，易与实际零占用混淆（中）

服务运行、流量与连接均有数据时，内存卡片持续显示 0 B。SSH 只读 `ps -o pid,rss,etime,comm -p 11962` 显示 RSS 79096 KiB，证明服务实际并非零内存占用；尚未定位内核接口或映射层原因。
建议缺失或不可获取时显示“不可用”，并明确是否支持当前内核版本。

证据：[概览桌面截图](screenshots/audit-20261024-dashboard-desktop.png)。

### UI-03：深色主题下图表刻度和汇总文字偏暗（低）

概览图表轴线、图例文字，以及配置对照顶部计数使用较暗灰色，扫描阅读费力。
主体表格对齐与分组清楚，但辅助状态的对比度弱于主体。

证据：[概览](screenshots/audit-20261024-dashboard-desktop.png)、[配置对照](screenshots/audit-20261024-compare-click.png)。

### UI-04：只读状态标签仍保留“应用 / 导入 / 应用后重启”（中）

DNS 状态与配置对照标签下仍显示设置页的全局“应用”“从配置文件导入”“应用后重启服务”。
用户正在阅读只读数据时也能接触到改变配置或触发重启的操作，且按钮没有在当前标签中解释作用范围。
建议仅在可编辑设置标签展示写入操作；只读标签保留“刷新”。本轮未点击这些按钮。

证据：[DNS 全页](screenshots/audit-20261024-dns-full.png)、[配置对照筛选结果](screenshots/audit-20261024-compare-differences.png)。

### UI-05：策略页缺少准确的“当前生效 / 待应用”分辨（高）

策略行显示 `opt2 / 全部 / US-AUTO / 创建`，下方只写“opt2 → US-AUTO · 应用后生效”。
DNS 页却已识别 opt2 走 TUN，SSH 也确认当前存在 route-to；页面未直接给出已安装规则的对账结果。
尤其当前 pf 规则是 TCP 全部、UDP 仅 53/500/4500，无法由“全部”这一个值读出真实协议覆盖。
这不证明插件产生了这些规则；它说明 UI 没有充分呈现当前设备状态，用户难以判断是否需要再次应用、或是否存在手工修改。

建议增加当前 pf 覆盖表，区分模型意图、文件规则、实际防火墙规则和未应用差异；接口显示 `LanUS (opt2)`，并明确 UDP 覆盖。
预览中还保留 `config.xml: ... / run: configctl filter reload` 英文实现文本，可改成用户可理解的变更说明。

证据：[策略页](screenshots/audit-20261024-routing.png)、[预览](screenshots/audit-20261024-routing-preview.png)、[DNS 状态](screenshots/audit-20261024-dns-full.png)；pf 取证摘要见本轮日志。

### UI-06：内核日志在文本框中显示 HTML 转义实体（中）

日志文本框中源与目标的箭头显示为 `--&gt;`。SSH 读取原始日志的一行则是正常 `-->`。
这降低阅读与复制检索的质量；建议文本框按纯文本显示，仅在真正需要生成 HTML 时转义。

证据：[日志页](screenshots/audit-20261024-logs.png)，静态可见，原始日志对比见本轮日志。

### UI-07：订阅执行状态与空日志缺少明确反馈（中）

订阅页只有地址/密钥、保存、开始订阅、重启复选框及大块空日志，没有最后成功时间、最近结果或当前是否执行中。
日志页切换到订阅日志后也是完全空白，未区分“尚无日志”“文件不存在”与“读取失败”。本轮仅确认空白表现，未触发订阅验证执行流程。
建议提供明确空态、最后读取时间、上次更新结果，将“开始订阅”改为作用明确的“更新订阅”。

证据：[订阅页](screenshots/audit-20261024-subscription.png)、[订阅日志空态](screenshots/audit-20261024-subscription-log-empty.png)。

### UI-08：日志工具栏的图标按钮缺少可读名称（低）

刷新 / 下载 / 清空均只显示图标。渲染 DOM 检查中这些按钮的 `title` 为空、`aria-label` 缺失；无障碍快照将其读作图标字符。
建议为按钮设置明确的可访问名称及悬停说明，尤其让“清空”明显区别于只读操作。

证据：[日志工具栏](screenshots/audit-20261024-logs.png)，DOM 检查摘要见本轮日志。

### UI-09：锁定的下拉字段呈现为空白灰块（中）

设置页加载完成后，“日志层级”和固定的“协议栈”在深色主题里显示为空白灰块。
同一页面的可访问快照及配置对照已有 `info` 和 `gvisor` 值，因此这是显示可读性问题，而非字段没有值。
桌面与 390px 窄屏均可见。建议禁用控件仍清楚显示当前值，固定字段可直接用只读文本展示。

证据：[设置桌面](screenshots/audit-20261024-settings-loaded.png)、[设置窄屏](screenshots/audit-20261024-settings-mobile.png)、[配置对照](screenshots/audit-20261024-compare-click.png)。

### UI-10：低速流量数字过长挤占统计卡片（中）

通过菜单重进概览后，下载速率显示 `738.2016890213612 B/s`，单位被挤到第二行，下载/上传说明在卡片底部被截断。
建议对 B/s 同样限制小数位，固定速率行高，避免采样得到小数时破坏布局。

证据：[概览菜单入口](screenshots/audit-20261024-dashboard-menu-entry.png)。静态截图直接记录该采样结果。

- 多页检查的浏览器 `errors` 为空；这不覆盖未执行分支，也不代表服务端日志全量审计。

## 视觉与适配

与[原生 Monit 状态页](screenshots/audit-20261024-native-monit.png)对照，插件沿用了相同的侧栏、标题条、背景与橙色操作按钮，视觉上属于 OPNsense。
Monit 当前未运行，故该页只能作为外框与状态信息样式参考，不能作为完整表格比较基准；本轮未启动 Monit。

1440×1000 桌面下主体表格对齐正常，配置对照比概览更易扫读。390×844 下侧栏折叠、页面宽度与视口均为 390px，未出现文档级横向溢出；标签与控件仍较拥挤，部分中文标签拆行。
本轮只检验当前深色主题，没有修改主题偏好，未验证浅色主题。

## 未改设置的核实与验证限制

检查前后以下内容的 SHA256 完全一致：

- `/conf/config.xml`
- `/etc/rc.conf.d/mihomo`
- `/usr/local/etc/mihomo/config.yaml`
- `/var/unbound/unbound.conf`
- `pfctl -sr`、`pfctl -sn` 的只读输出
- `netstat -rn -f inet` 的只读输出

mihomo PID 始终为 11962，未启停或重启。开机自启仍保持原来的 YES，未为符合文档而修改现状。
初始模板哈希路径写成了不存在的根路径，故不将模板计入前后校验；只读查找确认真实路径为 `/usr/local/etc/mihomo/sub/template_config.yaml`。
完整基线与复核输出保留在本轮本地 `logs/`，未导出配置内容或账号口令。

未执行保存、应用、导入、订阅更新、恢复、启停服务、测速、连接断开、策略启禁用、绑定自检或网络撤销。
因此本报告评估的是页面读取、交互入口和实际状态的匹配程度，不将写入流程、订阅成功率或代理性能判为通过。
无障碍自动检查返回了全零计数（连通过项也为零），不作为 WCAG 通过证据；按钮名称问题依据实际 DOM 与快照判断。
